# Native NPC discovery probe

Use a disposable Skyrim save and the development build, with the installed SkyrimNet, Magelight, PapyrusUtil, SKSE and powerofthree's Papyrus Extender. Add the installed SkyrimNet and Papyrus Extender source directories to the Papyrus compiler imports. The existing `LivingPastStage0.esp` supplies the player alias.

1. Open Living Past in Magelight, expand **Native NPC discovery probe**, and select **Enumerate loaded NPC bases**. A small handshake runs before enumeration. Record the unfiltered count, named unique count, native call time, enumeration round trip, page count, total page time, and slowest page. Type a name while results arrive, then repeat after the scan finishes. Record filter time with the full in-memory index and check whether the UI stays responsive between pages. If an operation times out, record the phase and any partial metrics shown.
2. For the save and dialogue check, enter the filename of a small plugin already loaded in the test profile and enumerate just its NPC bases. Search for a mod-added character and record the name and plugin shown. Select the row, enter a distinctive test history, and select **Activate test history**. Verify the readback identifies the same character and revision. Save to a new slot, reload that slot, and select **Read active test history** to verify the persisted record without rebuilding the catalog. Load an earlier disposable save and repeat the readback to check save isolation. **Clear test history** clears the active probe in the current save.
3. Speak to the selected NPC as the visible player. Inspect SkyrimNet's actual request prompt for the history and the Papyrus log for the matching revision and elapsed lookup time. Inspect another speaker's request, a hidden-player request, and a nearby or secondary character profile for leakage. In the same scene compare SkyrimNet prompt preparation with the test history active and cleared.

The probe uses one player-owned relationship and two staging banks under `LivingPast.NativeProbe.*`. It stores an actual ActorBase form. The decorator compares that form with the speaking actor's base and returns JSON containing only the revision. The guarded prompt reads the matching history from the player and checks the revision again. Existing Ysolda and Carlotta records retain precedence. Named unique is an initial count and can include named creatures or NPCs unavailable for dialogue. Search timing covers the in-memory filter. Page timing includes Papyrus filtering, framing and delivery to Magelight.

The probe matches exact bases. SkyrimNet's documented `kind: succession` declares continuity from one identity to another. A future Living Past mapping could honor an explicit, verified succession as an alias for the same relationship. Ordinary identity links include other arrangements such as possession and have separate memory-sharing rules. The probe has no evidence yet about how SkyrimNet resolves the decorator's Actor argument for a succession.

## First in-game measurements

On Skyrim 1.5.97 with Papyrus Extender 6.4.3 and the active development profile in the Nolvus Awakening instance, two calls returned 23,803 NPC bases in 67 and 66 ms. The 67 ms run took 257 ms including the request and reply through Magelight. SkyrimNet registered the decorator. The first catalog page timed out.

With bounded pages (`5d6b3fa`), `GetAllForms(43)` returned the same 23,803 bases in 67 ms and the Magelight round trip took 229 ms. The scan returned 291 named unique candidates from 1,556 examined bases across 389 pages in 216,783 ms. The reported Papyrus page time totaled 149,473 ms and the slowest successful page round trip was 766 ms. The following page, starting at index 1,556, timed out. The empty-query filter over the partial index displayed 0.00 ms. The partial count includes generic display names such as Prisoner. The scan did not establish a full eligible count or measure search against a complete index. Save readback and dialogue projection still need runtime validation.

The single-plugin scan (`84bd3dc`) returned Auri and Thistlefoot from `018Auri.esp`. Both passed the initial named unique filter. Enumeration took 98 ms in Papyrus and 265 ms over Magelight. The single page took 532 ms end-to-end, including 326 ms reported in Papyrus. The empty-query filter displayed 0.00 ms for the two candidates. Auri had no UUID mapping in the loaded save's SkyrimNet database when the scan ran.
